# 骑士足球队智能分组 v1.6

八人制业余足球队的分组工具：教练维护球员评分与位置资料，选本场出勤，生成两支尽量均衡的队伍，并查看位置覆盖与守门轮换。

> **内置数据是虚构的示例**：首次打开自带 16 名虚构球员（姓名、评分均为编造），方便直接体验全流程。用自己的真实花名册时，请按下面「导入真实数据」操作替换。

## 功能

- **球员档案**：九项能力评分（1–5，步长 0.5，空值就是空）、主位置/兼任位置、8 个位置的熟悉度、后场支点/组织接应标记，可新增、编辑、归档。
- **本场分组**：勾选出勤 → 填当天状态与伤病 → 生成分组 → 选方案 → 复制群公告 → 保存比赛快照。
- **位置覆盖**：阵型 3-3-1，7 个外场槽位与 Excel 位置一对一；覆盖只算擅长/熟悉；推荐方案按覆盖排序。
- **守门轮换**：每队 8 个时段，门将分不与外场分相加；支持「因伤不能守门」「因伤只能守门」。
- **比赛记录**：比分、射门、平衡感受、逐球事件（进球/主助攻/副助攻/乌龙）、分钟。
- **榜单与参考**：进球助攻榜（进球 +1，主助攻 +1，副助攻 +0.5）、搭档配合备注。
- **数据备份**：JSON 整体备份/导入、花名册 Excel 导入/导出、Excel 模板下载、页面自检。

## v1.6 规则摘要

- **位置**：只用 8 个位置——守门员、中后卫、左边后卫、右边后卫、后腰、左边前卫、右边前卫、中锋。守门员是第 8 个位置，只用于轮换。
- **覆盖**：只有擅长（代价 0）/熟悉（代价 1）算覆盖；应急（代价 3）、未评估（代价 4）只作未覆盖槽位填充；不适合禁止分配；无左右镜像。
- **分组**：枚举全部等人数分组；硬约束是每队至少一名已确认后场支点、至少一名已确认组织接应者（只算能踢外场的人），无可行方案时不自动放宽；先按能力取前 10 名（排序键：最大 Δ、体能+无球+回防 Δ 和、八项 Δ 和、稳定 ID 组合键），再按覆盖取前 3 名推荐（最弱时段覆盖高→低、未覆盖总数少→多、能力排名前→后），默认选中覆盖第 1 名。
- **输出名单**：两队内部名字每次生成时随机排列、黑/浅蓝归属抛硬币决定；只影响展示，分队、能力、覆盖、守门轮换不变；同一套方案在各处显示一致，重新生成才重新抽；比赛快照按当时的顺序与归属保存。
- **能力**：9 项评分 1–5、步长 0.5；空值永不补 0 或 3；守门评分不进外场平均与 Δ。
- **当天状态与伤病**（只在当天页面内存里，刷新就丢，场次或日期一换就清空，不保存在任何地方，比赛快照也不保存）：
  - 疲劳：正常不扣；稍疲劳体能 −0.5；明显疲劳体能 −1；未知不扣、显示待确认。
  - 伤病：无伤病不扣；轻伤速度 −0.5、体能 −0.5；带伤上场速度 −1、体能 −1、无球跑动 −0.5、回防补位 −0.5。
  - 扣分相加，每项最低 1 分，空仍为空，守门评分不受影响。**扣分幅度是试行参数，没有比赛数据支持。**
  - 「因伤不能守门」：任何时候都能勾（包括无伤病，比如手受伤），不扣分，只不进守门轮换，外场照常踢；改伤病不自动取消。
  - 「因伤只能守门」：只有伤病选了带伤上场才能勾；与「不能守门」二选一；伤病改回轻伤/无伤病自动取消；勾了的人整场固定守门、不踢外场，外场评分不计入本队平均（本队按 7 人算，对面按 8 人算）；一队最多一个，违反的分组方案直接排除。
- **群公告**：只出名单和预计位置，不公开能力分与负面评价。

## 导入真实数据

1. 在仓库里打开 `templates/球员评分模板.csv`（或在应用「数据备份」里点「下载 Excel 模板」）。
2. 按表头填表：每行一位球员；姓名必填、不可重复；主位置填 8 个位置之一；兼任位置多个用顿号分隔；九项评分填 1–5、步长 0.5，或留空；支点/接应填 是、否、未知。
3. 在应用「数据备份」→「导入花名册（.xlsx / .csv）」，上传填好的文件，预览确认后替换花名册。导入后基线分组按导入顺序前一半深黑、后一半浅蓝，请在「球员档案」里核对。
4. 位置熟悉度默认：主位置=擅长，兼任=熟悉，其余=未评估；想细调可在「球员档案」编辑页里逐格改。

## 本地运行

```bash
npm install
npm run dev      # 开发模式
npm run build    # 生产构建（产物在 dist/）
npm run preview  # 预览生产构建
npm test         # 单元测试（vitest）
npm run typecheck
```

数据保存在浏览器 localStorage（key：`knights-balancer-v16`），不经过任何服务器。

## 部署静态构建

```bash
npm run build
```

把 `dist/` 的内容放到任意静态托管（GitHub Pages、Netlify、Vercel、Nginx 等）即可。应用是纯前端，没有后端。
